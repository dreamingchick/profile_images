# Profile Images 웹서비스 기획서 (PRD)

- **버전:** 1.2 (Cloudflare 무료 운영·사용량 보호 반영)
- **수정일:** 2026-11-10
- **저장소:** https://github.com/dreamingchick/profile_images
- **서비스 성격:** 무료 프로필 이미지 제작 의뢰·결과물 공유·프롬프트 공유
- **개발 원칙:** 단일 출시 범위로 구성. 별도의 2·3단계 기능 확장 로드맵은 수립하지 않음.
- **기술 스택 확정:** Cloudflare Workers + D1 + R2 + Workers Static Assets + Turnstile.
- **운영 원칙:** 무료 사용량을 넘지 않도록 애플리케이션에서 보수적 할당량을 적용하며, Cloudflare의 과금은 별도로 점검한다.

## 1. 서비스 개요

**Profile Images**는 누구나 무료로 프로필 이미지 제작을 의뢰하고, 운영자가 제작한 결과물을 한 의뢰에 여러 장 등록하며, 공개에 동의한 결과물을 다른 방문자가 감상하고 다운로드할 수 있는 웹사이트다. 별도의 **프롬프트 공유 게시판**에서는 누구나 프로필 이미지 생성에 사용한 프롬프트를 등록하고 복사할 수 있다.

두 개의 공개 공간을 분리한다.

1. **작품 갤러리:** 운영자가 제작·등록한 완성 이미지를 공유하는 공간. 방문자는 열람·다운로드 가능.
2. **프롬프트 공유 게시판:** 방문자 누구나 이미지 제작용 프롬프트를 게시·열람·복사하는 공간. 운영자 승인 없이 작성되지만 스팸·위반 게시물 관리 대상.

이미지 자체는 운영자가 외부 제작 도구로 만들며, 웹사이트에 AI 생성 기능은 포함하지 않는다.

### 1.1 서비스 목표

- 비회원이 **텍스트만으로** 제작 의뢰를 접수한다.
- 필요하면 이미지 파일을 **선택적으로 여러 장 첨부**한다.
- 운영자가 **의뢰당 여러 장의 결과물**을 업로드하고 대표 이미지를 고른다.
- 의뢰인이 공개에 동의한 결과만 갤러리로 게시한다.
- 공개된 이미지는 누구나 원본 품질로 **개별 다운로드**한다.
- **누구나 비회원으로 프롬프트 게시글을 작성**하고, 다른 사람이 프롬프트를 한 번에 복사한다.
- 의뢰 내용과 개인 참고 파일은 기본 비공개로 유지한다.

### 1.2 제외하는 기능

결제·유료 등급·포인트·크레딧, 일반 사용자 계정 및 마이페이지, AI 생성 엔진, 이메일 알림, ZIP 묶음 다운로드, 댓글·좋아요, 제작 의뢰 수정·재요청 워크플로, 다운로드 통계 대시보드, 게시판 첨부 이미지 업로드, 추천 알고리즘 등은 **현재 개발 범위에 포함하지 않는다**. 필요할 때 새로운 기획을 별도로 수립하며, 2·3단계 확장 일정은 계획하지 않는다.

> 무료란 이용자의 의뢰·열람·다운로드·프롬프트 공유가 무료라는 의미다. 서버·도메인·이미지 보관·전송에는 사용량에 따라 운영 비용이 발생할 수 있다.

## 2. 이용자 및 권한

| 역할 | 의뢰 | 갤러리 | 프롬프트 게시판 | 운영 관리 |
|---|---|---|---|---|
| 방문자(비회원) | 새 의뢰 작성 가능 | 공개 작품 열람·다운로드 | 글 목록·상세 열람, 글 작성, 프롬프트 복사 | 불가 |
| 의뢰인(비회원) | 개인 조회 링크로 자신의 의뢰 진행 상태·결과 확인 | 동일 | 본인 글은 발급된 수정용 비밀 링크로 삭제 가능 | 불가 |
| 관리자 | 모든 의뢰 조회, 상태 변경, 결과 업로드 | 작품 공개·비공개·삭제 | 전체 글 숨김·삭제 | 인증 후 가능 |

일반 사용자 회원가입과 로그인은 없다. 관리자 로그인만 제공한다.

## 3. 주요 이용 흐름

### 3.1 제작 의뢰

1. `제작 의뢰` 페이지에서 닉네임, 제목, 요구 사항을 작성한다.
2. 참고 이미지 0~5장을 선택적으로 첨부한다.
3. 완성 결과물의 공개 갤러리 게시 동의 여부를 선택한다. **기본은 미동의**다.
4. 의뢰를 제출하면 접수번호와 **비공개 조회 링크**를 발급한다.
5. 의뢰인은 해당 링크에서 현재 상태와 완성 이미지를 본다.

### 3.2 운영자의 제작 결과 등록

1. 관리자가 접수된 의뢰를 확인한다.
2. 진행 상태를 변경하고 외부 제작 도구에서 이미지를 제작한다.
3. 완성 이미지를 한 번에 여러 장 업로드한다.
4. 순서를 조정하고 대표 이미지를 선택한다.
5. 의뢰인 동의가 있는 경우에만 `갤러리에 게시`한다.
6. 갤러리 미게시 의뢰는 의뢰인만 개인 링크로 결과물을 확인한다.

### 3.3 갤러리 열람·다운로드

1. 사용자는 갤러리의 1:1 썸네일 목록에서 작품을 선택한다.
2. 상세 화면에서 해당 의뢰로 제작된 결과물 여러 장을 본다.
3. 원하는 이미지를 **각각 원본 파일로 다운로드**한다.

### 3.4 프롬프트 공유

1. 사용자는 `프롬프트 공유` 메뉴에서 게시글 목록을 본다.
2. `프롬프트 올리기`를 클릭한다.
3. 게시글 제목, 닉네임, 이미지 생성 프롬프트를 입력한다. 부연 설명은 선택이다.
4. 공개 게시 조건에 동의하고 등록하면 글이 게시된다.
5. 작성자는 게시 완료 화면에 표시되는 **수정·삭제용 비밀 링크**를 보관할 수 있다.
6. 다른 방문자는 글을 읽고 `프롬프트 복사`로 전체 프롬프트를 클립보드에 복사한다.
7. 관리자는 스팸·광고·부적절한 글을 비공개 또는 삭제할 수 있다.

프롬프트 게시글은 **별도의 콘텐츠 유형**이며, 관리자가 업로드한 갤러리 작품과 자동으로 연결되거나 갤러리에 노출되지 않는다.

## 4. 기능 명세

### 4.1 의뢰 접수

| 항목 | 필수 | 기본 규칙 |
|---|---|---|
| 닉네임 | 필수 | 실명 불필요 |
| 의뢰 제목 | 필수 | 최대 100자(제안) |
| 상세 요구 사항 | 필수 | 최대 5,000자(제안), 줄바꿈 허용 |
| 참고 이미지 | 선택 | 0~5장, PNG/JPG/WEBP, 각 최대 10MB(제안) |
| 희망 이미지 비율 | 선택 | 기본 1:1 |
| 이메일 | 선택 | 제공 시에도 자동 알림 기능 없음. 필요 없으면 양식에서 제거 가능 |
| 결과 공개 동의 | 선택 | 기본 비동의. 비동의라면 갤러리에 게시 불가 |
| 개인정보·업로드 권한 안내 | 필수 | 목적·보관·철회 방법 안내 및 동의 |

- 참고 이미지 첨부 없이 텍스트만으로 제출 가능.
- 첨부 시 미리보기·파일 제거·재선택 가능.
- 중복 제출 방지, 업로드 오류 표시, 폼 내용 보존.
- 성공 시 접수번호와 추측 불가능한 임의 접근 토큰 기반 개인 조회 링크 제공.

### 4.2 개인 의뢰 조회

- 링크 보유자가 접수 내용의 최소 정보, 진행 상태, 공개 여부, 완성 이미지 및 개별 다운로드를 확인.
- **접수번호만으로 개인 의뢰를 조회할 수 없음.**
- 개인 링크 공유 시 접근 권한도 함께 넘어간다는 주의 문구 제공.
- 비공개 참고 이미지는 관리자만 열람하며 공개 갤러리에서 사용하지 않음.

### 4.3 관리 기능

- 관리자 로그인.
- 상태별 접수 목록 및 접수번호·제목 검색.
- 의뢰 상세 내용 및 참고 이미지 확인.
- 상태: `접수`, `검토 중`, `제작 중`, `완료`, `보류`, `반려`.
- 관리자 메모.
- 결과 이미지 **최대 20장(제안), 파일별 20MB(제안)** 다중 업로드.
- 결과물 개별 삭제·교체, 순서 변경, 대표 이미지 선택.
- 공개 동의를 받은 `완료` 의뢰 중 결과 이미지가 있는 작품만 갤러리에 게시.
- 게시 취소, 게시물 삭제, 프롬프트 게시글 숨김·삭제.

### 4.4 공개 갤러리

- 공개 승인된 완성 작품만 목록에 노출.
- 정사각형 썸네일, 제목, 의뢰 닉네임, 게시일.
- 최신순 정렬과 제목 검색.
- 작품 상세에서 동일 의뢰에 등록된 여러 장의 결과물을 그리드·확대 보기로 제공.
- **이미지별 다운로드**. 다운로드되는 원본의 실제 비율·해상도 보존.
- 공개 갤러리에는 의뢰 원문, 첨부 참고 파일, 이메일, 관리자 메모, 개인 조회 토큰을 절대 노출하지 않음.

### 4.5 프롬프트 공유 게시판 (신규 핵심 기능)

**누구나 회원가입 없이 글을 작성할 수 있는 텍스트 중심 게시판**으로 구현한다.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 게시글 제목 | 필수 | 최대 100자(제안) |
| 작성자 닉네임 | 필수 | 실명 불필요, 동일 닉네임 사용 가능 |
| 프롬프트 원문 | 필수 | 최대 10,000자(제안), 줄바꿈·특수문자 보존 |
| 설명·활용 팁 | 선택 | 최대 2,000자(제안) |
| 게시글 삭제·관리 | 자동 | 작성 직후 발급되는 비밀 관리 링크 사용, 관리자 별도 권한 |

**게시판 기능**
- 목록: 제목, 닉네임, 등록일, 프롬프트 미리보기.
- 제목·본문 키워드 검색, 최신순 정렬.
- 상세: 원문 전체 표시, 줄바꿈과 기호를 유지한 텍스트 렌더링.
- `프롬프트 복사`: 원문을 한 번에 클립보드로 복사, 성공·실패 피드백 제공.
- `글쓰기`: 비회원에게 개방. 실명·이메일·회원가입 불필요.
- `내 글 삭제`: 글 등록 시 발급한 비밀 관리 링크로만 허용. 원문 수정은 제공하지 않음(단순화).
- 관리자는 관리자 화면에서 게시글 숨김·삭제.
- 욕설·광고·도배·타인 권리 침해 콘텐츠 등 운영 기준에 해당하는 글은 관리자가 조치.
- 프롬프트 게시판에 이미지 파일 첨부, 댓글, 좋아요, 조회수, 태그, 신고 버튼은 우선 포함하지 않음.

**보안·스팸 방지**
- 업로드뿐 아니라 익명 게시글 작성에도 IP/세션 기반 속도 제한과 CAPTCHA 또는 유사 자동화 방지 도입.
- 게시글은 HTML을 실행하지 않는 안전한 텍스트로 표시해 XSS 공격 방지.
- 게시글 관리 토큰은 데이터베이스에 해시 형태로 저장.
- 글을 숨겨도 게시글 원본이 운영자에게 보존되는지와 삭제 처리 방식은 운영 정책에 명시.
- 악의적 대량 등록 방지를 위해 글자 수·요청 빈도 제한.

## 5. URL 및 화면 구성

| 경로 | 화면 | 주요 내용 |
|---|---|---|
| `/` | 홈 | 서비스 소개, `제작 의뢰`, `작품 갤러리`, `프롬프트 공유` 진입 |
| `/request` | 제작 의뢰 | 텍스트 요청, 선택적 이미지 첨부, 공개 동의 |
| `/request/success` | 접수 완료 | 접수번호, 개인 조회 링크 |
| `/track/[token]` | 의뢰 상태·결과 | 접수 상태, 제작 결과, 개별 다운로드 |
| `/gallery` | 작품 갤러리 | 공개 작품 목록, 검색 |
| `/gallery/[slug]` | 갤러리 상세 | 의뢰별 다중 결과물, 이미지별 다운로드 |
| `/prompts` | 프롬프트 게시판 | 공개 게시글 목록, 검색, 글쓰기 이동 |
| `/prompts/new` | 프롬프트 글쓰기 | 닉네임, 제목, 프롬프트 입력 |
| `/prompts/[id]` | 게시글 상세 | 원문 확인, `프롬프트 복사` |
| `/prompts/manage/[token]` | 내 글 관리 | 비밀 링크로 본인 게시글 삭제 |
| `/admin/login` | 관리자 로그인 | 관리자 인증 |
| `/admin` | 관리자 대시보드 | 의뢰 목록·요약 |
| `/admin/requests/[id]` | 의뢰 관리 | 상태, 결과 업로드, 갤러리 게시 |
| `/admin/prompts` | 프롬프트 관리 | 전체 게시글 조회·숨김·삭제 |
| `/admin/usage` | 무료 한도 사용량 | R2 저장·요청 사용량, D1·Workers 지표, 업로드 차단 상태 |
| `/privacy` | 개인정보 처리 안내 | 수집·보관·삭제·권한 관련 안내 |
| `/terms` | 이용 안내 | 무료 이용, 콘텐츠 권리, 공개·다운로드 규정 |

**상단 내비게이션:** `홈 | 작품 갤러리 | 프롬프트 공유 | 제작 의뢰`.

## 6. 데이터 구조

| 테이블 | 역할 | 핵심 필드 |
|---|---|---|
| `requests` | 이미지 제작 의뢰 | `id`, `request_no`, `title`, `requester_nickname`, `description`, `aspect_ratio`, `status`, `public_consent`, `visibility`, `access_token_hash`, `admin_note`, 타임스탬프 |
| `request_attachments` | 의뢰 참고 이미지 | `id`, `request_id`, `storage_path`, `filename`, `file_size`, `mime_type`, `sort_order` |
| `result_images` | 완성 이미지 | `id`, `request_id`, `storage_path`, `thumbnail_path`, `filename`, `width`, `height`, `sort_order`, `is_cover` |
| `prompt_posts` | 프롬프트 공유글 | `id`, `title`, `author_nickname`, `prompt_text`, `description`, `status`, `management_token_hash`, `created_at`, `updated_at` |
| `storage_quota` | 저장 용량 제한 및 일시 중지 | `confirmed_bytes`, `reserved_bytes`, `hard_limit_bytes`, `uploads_paused` |
| `upload_reservations` | 동시 업로드 예약/복구 | `id`, `owner_id`, `reserved_bytes`, `status`, `expires_at` |
| `usage_snapshots` | 사용량 기록 | `source`, `storage_bytes`, `class_a_ops`, `class_b_ops`, `checked_at` |

**데이터 관계:** `requests` 1건에 `request_attachments` 여러 건과 `result_images` 여러 건을 연결. `prompt_posts`는 독립 테이블로 분리하여 누구나 작성 가능하도록 한다.

**게시글 상태:** `published`(공개), `hidden`(관리자 숨김), `deleted`(삭제). 일반 방문자는 `published`만 조회한다.

**공개 판정:** 결과물은 `requests.visibility = published`이고 `public_consent = true`이면서 게시 가능한 이미지가 존재할 때만 갤러리에 노출한다. 접근 검사는 서버 측에서도 실시한다.

## 7. 확정 기술 및 운영 구조

| 구분 | 사용 기술 | 역할 |
|---|---|---|
| 화면 | React + TypeScript + Tailwind CSS (정적 빌드) | 의뢰·갤러리·프롬프트·관리자 화면 |
| 정적 페이지 배포 | Cloudflare Workers Static Assets | HTML/CSS/JS 제공, 정적 요청 무료 |
| 서버 API | Cloudflare Workers (Free) | 권한 확인, 유효성 검사, API, 업로드·다운로드 게이트웨이 |
| 데이터베이스 | Cloudflare D1 | 의뢰, 이미지 메타데이터, 게시글, 사용량 예약/집계 |
| 파일 저장 | Cloudflare R2 Standard | 참고 원본, 완성 원본, 썸네일 (서로 다른 버킷 또는 접두사) |
| 비회원 스팸 방지 | Cloudflare Turnstile + Workers의 서버 검증·속도 제한 | 의뢰·게시글·업로드 남용 방지 |
| 관리자 인증 | Workers 서버 측 인증 세션(또는 Cloudflare Access의 적용 가능성 검토) | 관리 기능 보호 |
| 소스코드 | GitHub `dreamingchick/profile_images` | 소스·기획서 버전 관리 |

**배포 방식:** React SPA 또는 정적 생성 기반으로 빌드한다. Next.js 서버 렌더링을 전제로 하지 않는다. 정적 페이지는 Static Assets로 제공하고 동적 작업만 Worker API로 처리한다. 서버 API 무료 요청 한도에 갤러리의 매 이미지 파일을 포함시키지 않도록 썸네일 캐싱을 우선한다.

**이미지 접근:** 모든 R2 버킷은 기본적으로 비공개로 운영한다. 처음에는 Worker가 접근 권한을 확인하고 이미지를 전달한다. 서비스 규모가 커져 자체 도메인이 생기면 공개 이미지 전용 버킷을 분리해 커스텀 도메인 CDN 캐시를 이용할 수 있다. 의뢰 참고 파일 및 비공개 결과 파일은 절대 공개 버킷에 넣지 않는다. R2 `r2.dev` 공개 개발 주소를 운영 서비스의 본 이미지 전달 주소로 사용하지 않는다.

### 7.1 Cloudflare 무료 한도와 자체 안전 기준

2026-11-10 공식 안내 기준. 제공 한도는 이후 변동 가능하므로 배포 시 공식 문서 재확인.

| 서비스 | 무료 한도 | 권장 자체 운영 기준 | 한도 접근 시 동작 |
|---|---|---|---|
| R2 Standard 저장 | 10 GB-month/월 | 활성 객체와 예약분을 포함해 8,000,000,000바이트 | 새 이미지 업로드 중단 |
| R2 Class A | 월 100만 작업 | 월 70만~80만 회에서 경고·업로드 제한 검토 | 이미지 작성/복사/목록 남용 제한 |
| R2 Class B | 월 1,000만 작업 | 월 700만~800만 회에서 경고·비정상 트래픽 차단 | 캐시 활용, 봇 요청 억제 |
| Workers Free | 일 10만 동적 호출 | 정상 트래픽 중심 운영, 쓰기 작업은 별도 속도 제한 | 플랫폼 한도에서는 오류 가능, 기능별 제한 구현 |
| D1 Free 읽기 | 일 500만 행 | 검색 인덱스·페이지네이션 적용 | 복잡한 검색 축소 가능 |
| D1 Free 쓰기 | 일 10만 행 | 게시글·의뢰 등록 횟수 제한 | 쓰기 기능부터 단계적 중단 |
| D1 Free DB 크기 | 데이터베이스 하나당 500MB, 계정 총 5GB | DB 350MB 경고, 400MB 근처 정리·추가 쓰기 제한 | 게시글/의뢰 신규 저장 차단 가능 |

**한계:** R2 무료 용량 10GB는 단순한 순간 저장량 상한이 아니라 월평균 GB-month 기준이며, 읽기/쓰기 작업 횟수도 과금 대상이다. R2 Standard 버킷에는 무료 10GB를 강제로 넘지 못하게 하는 요금 상한 장치가 자동 적용되는 것이 아니다. 따라서 '100% 과금 방지'로 보증하지 않는다. 별도 API/대시보드/공유 키로 발생한 작업, 측정 지연, 구현 오류 등은 웹 애플리케이션 제한을 우회할 수 있다. Cloudflare 예산 알림 역시 사용량을 멈추지 않는다.

### 7.2 업로드 단계별 자동 제어 정책

**기본 정책안 (운영자 조정 가능):**

1. 0~7GB: 사용자 참고 이미지 첨부 및 관리자 결과 업로드 허용.
2. 7~8GB: 사용자 참고 이미지 첨부 차단. **텍스트만의 제작 의뢰는 계속 허용.** 관리자 결과 업로드는 남은 용량 이내에서만 허용.
3. 8GB 이상: 모든 새 이미지 업로드 차단. **기존 갤러리 조회·다운로드, 텍스트 의뢰, 프롬프트 게시판은 계속 제공**(각 서비스의 요청·DB 한도 이내일 때).
4. 용량 회수 후: 백그라운드 대조 절차를 거쳐 업로드를 재개. 사전에 중단되었던 업로드를 자동으로 무작정 재시도하지 않음.

**개별 업로드 제한:** 방문자 참고 이미지 0~5장, 1개 파일 최대 10MB, 의뢰별 총 20MB를 기본값으로 권고. 관리자 결과물은 의뢰당 최대 20장, 파일당 20MB, 의뢰당 총 100MB 이내를 권고. 원본 파일을 변형하지 않고 별도 작은 썸네일 파일을 만든다. 정책값은 앱 설정에서 변경할 수 있지만 하드 스토리지 상한이 우선한다.

**예시:** 현재 저장량 7.95GB이고 관리자 결과 이미지 80MB를 추가하려면 총량 8.03GB가 되어 서버에서 거절한다. 브라우저 화면에만 제한을 두지 않고 Workers가 D1 예약 용량을 확인해 처리한다.

### 7.3 동시 업로드·오류에 강한 업로드 흐름

1. 브라우저는 업로드 파일명·타입·크기를 표시하고 클라이언트에서 빠르게 검사한다. 이는 UX용 사전 검증이지 보안 장치는 아니다.
2. Workers는 관리자 권한 또는 유효한 의뢰 접수 흐름을 확인하고, Turnstile·속도 제한·파일 형식·크기·개수·공간을 다시 검증한다.
3. Workers는 D1에 **업로드 예약 공간**을 기록한다. 할당량 조건을 포함한 원자적 조건부 갱신을 사용해 동시에 여러 요청이 들어와도 남은 공간을 중복 할당하지 않는다.
4. 허용된 요청만 비공개 R2 버킷에 스트리밍 업로드한다. R2 접근 키는 브라우저로 보내지 않는다.
5. R2가 반환하는 실제 바이트 수를 기준으로 D1 이미지 메타데이터와 사용량을 확정한다. 예약한 양보다 작다면 남은 예약 공간을 반환한다.
6. 오류/취소/시간 초과 시 예약 해제 및 혹시 남아 있는 객체 삭제를 재시도한다. 예약에는 만료시간을 둔다.
7. 정기 점검 시 D1 업로드 장부와 R2의 실제 객체/사용량을 대조해 오차를 교정한다. 별도 Cloudflare R2 공식 사용량 분석 지표와도 비교한다.
8. 삭제 시 R2 원본 및 썸네일이 실제로 삭제된 뒤에만 장부에서 해당 용량을 회수한다. 미삭제 객체는 남은 용량에 계속 포함한다.

**동시성 보장 주의:** R2 저장과 D1 메타데이터는 서로 다른 시스템이므로 완전한 단일 트랜잭션이 아니다. 실패 복구·예약 만료·주기적 대조 작업이 필요하다.

### 7.4 관리자 사용량 대시보드 (정식 핵심 기능)

`/admin/usage` 페이지 추가. 관리자는 다음 정보를 확인한다.

- R2 추정 사용량(파일별 `size` 합산), 진행 중 예약 용량, 총 8GB 내부 제한 대비 사용률.
- 사용자 첨부 업로드 허용/중단, 관리자 결과 업로드 허용/중단, 마지막 대조 시각.
- R2 Cloudflare 공식 사용량 지표: Class A/B 요청 수와 스토리지 지표(집계 지연 표시).
- Workers API 호출량, D1 읽기·쓰기 행 사용량(정확한 공식 지표가 제공되는 곳은 공식 대시보드 또는 API 조회).
- 최근 업로드 거절 사유·용량 경고·실패 복구/정리 이력.

관리자가 수동으로 업로드를 일시 중단할 수 있는 기능도 제공한다. 수동 중단과 자동 중단 중 더 엄격한 정책을 적용한다.

### 7.5 비용·트래픽 보호 세부 규칙

- **R2 저장:** `Standard`만 사용해 Infrequent Access의 추가 다운로드/보관 정책 과금을 피한다.
- **R2 요청 수:** 공개 이미지 캐시를 최대한 활용하며 갤러리 목록은 페이지네이션, 이미지는 지연 로드한다. 한 이미지 조회를 여러 번 R2에서 읽지 않도록 한다. 관리자 사용량 조회를 위해 R2 `list`/`head`를 불필요하게 반복하지 않는다.
- **Workers Free:** 정적 파일은 Static Assets에서 직접 제공하여 동적 Workers 요청과 분리한다. 플랫폼에서 일 10만 Worker 요청에 도달하면 서비스 오류가 발생할 수 있으므로 정상 동작을 보증할 수 없다. 무차별 이미지 요청과 자동 조회를 줄인다.
- **D1 Free:** 게시판 검색에 인덱스와 LIMIT를 사용하고 공개 갤러리도 페이징한다. 매 이미지 조회마다 D1 카운터를 쓰지 않는다. D1의 공식 사용량을 주기적으로 확인한다.
- **비회원 도배:** Turnstile 서버 검증, IP·시간대별 접수 제한, 중복 제출 방지, 용량 예약 방식을 조합한다. IP 정보는 목적에 맞게 최소 수집·보관한다.
- **알림:** 여유가 있다면 Cloudflare 계정의 예산 알림과 사용량 분석을 추가로 설정한다. 알림은 **과금 차단 기능이 아니다**.
- **외부 경로:** Cloudflare 대시보드 및 별도 API 키로 수동 업로드하는 경우에도 앱 추정치가 실제와 달라질 수 있으므로 관리용 API 키 배포를 최소화한다.

### 7.6 데이터 모델 추가

기존 `requests`, `request_attachments`, `result_images`, `prompt_posts`는 유지한다. 다음 테이블을 추가한다.

| 테이블 | 용도 | 핵심 필드 |
|---|---|---|
| `storage_quota` | 용량 합계·할당량·긴급 정지 플래그 | `id`, `confirmed_bytes`, `reserved_bytes`, `hard_limit_bytes`, `user_upload_limit_bytes`, `uploads_paused`, `updated_at` |
| `upload_reservations` | 동시 업로드와 실패 복구 | `id`, `owner_type`, `owner_id`, `reserved_bytes`, `status`, `expires_at`, `created_at` |
| `usage_snapshots` | 사용량 대조 결과 및 경고 | `id`, `source`, `storage_bytes`, `class_a_ops`, `class_b_ops`, `checked_at` |

`storage_quota`의 `confirmed_bytes + reserved_bytes`를 기준으로 조건부 갱신한다. 실제 R2 사용량이 앱 추정치보다 클 때는 실제값을 기준으로 업로드를 보수적으로 제한한다. 모든 시간 기반 한도는 UTC 기준으로 집계하며 화면에는 한국 시간(KST)으로 표시한다.

### 7.7 무과금 운영 목표의 판정

**목표:** 일반적인 사용에서 월 0원에 최대한 가깝게 유지한다. 그러나 R2 사용량은 요금이 발생할 수 있어 0원 보증은 불가능하다. 실제 과금 방지가 절대적인 필수 조건이라면 R2에 대한 별도의 계정 수준 사용 제어나 과금 방지 정책을 계약 단계에서 확인해야 하며, 없을 경우 일정한 잔여 위험을 수용해야 한다.

**검수 조건:** 업로드 8GB 제한, 7GB 사용자 첨부 제한, 동시 업로드 초과 방지, 비정상 파일 거부, 업로드 실패 정리, 공개/비공개 접근 분리, 프롬프트 게시판의 텍스트 저장 지속, 공식 사용량과 앱 장부 대조 기능을 시험한다.

## 8. UI 방향

**디자인:** 밝고 절제된 화이트 배경. 갤러리의 이미지가 주연이며, 원본 이미지의 스타일을 강제로 변경하지 않는다.

- **홈:** 메뉴별 3개 진입점(제작 의뢰 / 갤러리 / 프롬프트 공유)과 최신 공개 작품.
- **의뢰:** 한 화면에 작성·이미지 선택·미리보기·제출.
- **갤러리:** 1:1 카드 그리드; 상세에서 다중 이미지와 개별 다운로드.
- **프롬프트:** 이미지 그리드가 아닌 텍스트 목록; 상세에서 프롬프트를 읽고 `복사`하는 경험에 집중.
- **관리자:** 의뢰 목록, 결과물 관리, 프롬프트 게시글 관리, 사용량 모니터링.
- **모바일:** 입력 폼·복사 버튼·다운로드 버튼을 터치 친화적으로 배치.

## 9. 보안·이용 규정

1. 방문자의 이미지 의뢰와 프롬프트 게시글은 모두 무료로 제공한다.
2. 비공개 의뢰와 참고 이미지가 공개 화면, 검색 결과, 소스 코드, 로그에 노출되지 않도록 한다.
3. 사용자 공개 동의가 없는 결과물은 운영자가 임의로 갤러리에 게시하지 않는다.
4. 프롬프트 게시판은 공개 텍스트 공간이므로 민감한 개인정보와 무단 공유 콘텐츠 게시를 금지한다.
5. 프롬프트 공개·복사 기능은 자동으로 모든 이용·재배포 권한을 부여한다는 의미가 아니다. 권리 및 이용 고지를 별도 제공한다.
6. 관리자 토큰과 데이터베이스 비밀키는 브라우저에 노출하지 않는다.
7. 파일 실제 MIME/크기 확인, 비회원 요청 빈도 제한, XSS 방지, Workers 서버 권한 검사를 적용한다.
8. 게시글 등록과 의뢰 접수, 파일 업로드에 스팸 방지·남용 대응 수단을 적용한다.
9. 보관 기간, 데이터 삭제, 공개 철회 절차는 운영 정책에 명시한다.
10. 무료 한도 자체 제한과 Cloudflare 실제 과금 한도를 구분하고, 업로드 제한만으로 비용 0원을 절대 보장한다고 안내하지 않는다.
11. R2 접근 경로는 Workers가 통제하며, 외부 공개 버킷이나 관리자용 API 키가 우회 통로가 되지 않도록 한다.

## 11. 확정 사항 요약

- 사용자 이용 요금은 **무료**.
- **2·3단계 확장 기능은 계획하지 않음**.
- 기능 구역은 **제작 의뢰 / 공개 갤러리 / 프롬프트 공유 게시판 / 관리자**.
- 갤러리는 **운영자가 결과물을 등록하는 공간**이며, 게시판은 **누구나 프롬프트를 작성하는 공간**.
- 두 공간은 독립적으로 운영. 프롬프트 게시글이 갤러리 작품을 자동 등록·수정하지 않음.
- 의뢰에는 참고 이미지를 첨부하지 않아도 됨.
- 완성 결과물은 의뢰당 여러 장 업로드할 수 있음.
- 회원가입은 요구하지 않으며 관리자 로그인만 사용.
